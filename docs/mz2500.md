# Adding the MZ-2500 / MZ-2520

What it would take to emulate the Sharp MZ-2500 ("Super MZ", 1985) and the MZ-2520 in this core, as of 2026-10-03. Research only;
nothing here is implemented. **Update 2026-10-05:** the MZ-2500 is now a separate project,
https://github.com/alanswx/SharpMZ2500_MiSTer, which carries on from this research (its `docs/` and `TODO.md`).

**Short answer:** it is a new machine, not a variant. Little beyond the CPU, the 8255/8253/PIO, the floppy controller and the tape
path can be reused. The video controller, MMU, interrupt controller, YM2203, RTC, kanji/dictionary ROM access and keyboard are new.
Its memory (256 KB main RAM, 128 KB VRAM, 640 KB of kanji/dictionary ROM) does not fit beside the current models in block RAM, so
it needs SDRAM. Build it as a separate MiSTer core (or a second top level/RBF in this repo), sharing the common RTL. Estimate:
about 4-6 months of part-time work to reach "runs most of the MAME software list".

## 1. Hardware

Sources: MAME `src/mame/sharp/mz2500.cpp` ([GitHub](https://github.com/mamedev/mame/blob/master/src/mame/sharp/mz2500.cpp)),
Takeda Toshiya's EmuZ-2500 in the Common Source Code Project
([site](https://takeda-toshiya.my.coocan.jp/mz2500/index.html),
[mirror source `vm/mz2500/`](https://github.com/Artanejp/common_source_project-fm7/tree/master/source/src/vm/mz2500)),
[eaw.app specifications](https://eaw.app/sharpmz-2500-specifications/), [Wikipedia](https://en.wikipedia.org/wiki/MZ-2500),
[I/O map (maroon.dti.ne.jp, Japanese)](http://www.maroon.dti.ne.jp/youkan/mz2500/iomap.html),
[AKIBA PC Hotline retro column (Japanese)](https://akiba-pc.watch.impress.co.jp/docs/column/retrohard/1371267.html).

| Block | MZ-2500 |
|---|---|
| CPU | Z80B, 6 MHz (24 MHz crystal / 4). 4 MHz in MZ-80B/2000 mode. One M1 wait state at 6 MHz; waits on VRAM access during display. |
| Memory map | MMU: eight 8 KB windows (ports B4 = window index, B5 = page, B7 = mode). Page numbers 0x00-0x3F select from a 512 KB space. IPL reset maps pages 34-37 (IPL) at 0000-7FFF. |
| Physical pages (MAME) | 00-1F main RAM 256 KB; 20-2F graphics VRAM 128 KB; 30-33 VRAM read-modify-write/plane window; 34-37 IPL ROM 32 KB; 38 text VRAM (6 KB used); 39 kanji ROM / PCG window; 3A dictionary ROM window (bank port CE); 3C-3F phone ROM. |
| RAM | 128 KB main standard, 256 KB maximum; VRAM 64 KB standard, 128 KB maximum; PCG RAM 8 KB (CSP) / 14 KB (eaw). |
| ROMs | IPL 32 KB, CG 2 KB, kanji 256 KB (JIS level 1+2), optional dictionary 256 KB (MZ-1R28; standard on the MZ-2531), optional MZ-1R13 kanji 128 KB, phone ROM 16 KB (MZ-1E26). |
| Text | 80 x 25/20/12 (8 colours) or 40 x 25/20/12 (up to 64 colours); attributes (reverse, blink), PCG with combine modes, kanji characters from the kanji ROM, hardware scroll. Own CRTC register set (ports F4-F7). |
| Graphics | 640 x 400 x 4 colours, 640 x 200 x 16 colours (two screens), 320 x 200 x 16 (two screens), 320 x 200 x 256 colours. Windowed display, dot scroll in both directions, text/graphics priority. Separate register set (ports BC-BD), plane latches and a compare read (BC-BF). |
| Palette | 16-colour digital, 256-colour mode (`GGRRBBII` with per-plane enables), 4096-colour analogue palette (port AE) for 16 of the colours. |
| Video timing | 400-line: 55.49 Hz, 448 lines, 24.86 kHz, 21.477 MHz dot clock. 200-line: 60.99 Hz, 262 lines, about 15.98 kHz, 14.32 MHz. Chosen by a front-panel switch (CSP; values from x1center.org). |
| Sound | YM2203 OPN at 2 MHz (24 MHz / 12): 3 FM + 3 SSG. OPN port A drives the mouse select, port B reads the mode and 200/400-line switches. 1-bit beeper. |
| I/O | 8255 (E0-E3: tape, IPL/reset, beeper), 8253 (E4-E7, CLK0 = 31.25 kHz), Z80 PIO (E8-EB: keyboard matrix), Z80 SIO (A0/B0: RS-232C, mouse on channel B), RP5C15 RTC (CC), joysticks (EF, Atari/MSX type), printer (FE-FF), interrupt vector registers (C6/C7: CRTC, 8253, printer, RTC). |
| Floppy | MB8876 (inverted bus) at D8-DB, drive select DC, side DD, density DE. Built-in 3.5" 2DD, 640 KB (80 x 2 x 16 x 256). Up to 4 drives. |
| Tape | Built-in software-controlled data recorder with APSS, same 8255 control as the MZ-80B/2000 (CSP shares one `cmt.cpp` across EmuZ-80B/2200/2500). |
| Expansion | Two MZ-80 type slots; SASI HDD (MZ-1E30), EMM (MZ-1R37), LAN boards (later, DIY). Not needed for a first version. |

**MZ-80B/2000 compatibility.** A front-panel slide switch selects MZ-2500, MZ-2000 or MZ-80B mode. It is read through OPN port B
at boot. The 2500's own IPL then switches the hardware: CPU to 4 MHz, the MMU mode register (B7) to the 80B or 2000 memory layout,
and the CRTC (text register 0F) to draw the 2000 or 80B screen. It is the same hardware in a different mode, not a second machine.

**Models.** MZ-2511 (one drive), MZ-2521 (two drives), MZ-2531 "Super MZ V2" (dictionary ROM, more memory, TV control as standard),
MZ-2520 (budget: no data recorder, no MZ-80B/2000 modes; own IPL `ipl2520.rom`). The MZ-2861 (MZ-2800) is a 16-bit machine and out of scope.

## 2. What exists

| Implementation | State |
|---|---|
| MAME `mz2500` / `mz2520` (Angelo Salese) | `MACHINE_IMPERFECT_GRAPHICS`. Its TODO: kanji cut in half in non-interlace mode, reverse/blink attributes, missing SIO/HDD, no MZ-80B/2000 mode, mouse select line from OPN port A missing. Software list `mz2500_flop`: 75 disks, 31 supported, 26 partial, 18 not supported. |
| EmuZ-2500 (Takeda Toshiya, Common Source Code Project, GPLv2) | The most complete reference: all three boot modes, cycle-level waits, VRAM waits, CMT with APSS, SASI, MZ-1R12/1R13/1R37/1E26/1E30. Takes D88, MZT/CAS tape, HDD images. |
| FPGA | None found. GitHub searches ("mz2500 fpga/verilog/vhdl") return nothing; NibblesLab has `mz80b_de0` and `mz80c_de0` only. The original author's v2 (eaw.app) lists the MZ-2500 as "planned" (a model constant only). |

These are copyrighted Sharp ROMs: like the other MiSTer computer cores, the core should load them from the SD card, not embed them.

## 3. Software

- `software/Sharp Mz-2500.zip`: only two titles, Champion Pro-Wrestling Special and Flicky. Each is a loader (`.mzt`/`.cas`) plus
  raw memory dumps (`*.DAT`) that must be injected through EmuZ-2500's debugger (`command.txt`: breakpoints, `L addr` loads,
  `R PC`). They are not usable as tapes; a core would need a "load file at address and jump" debug path to run them.
- Most MZ-2500 software is on floppy: D88 images (the MAME list, the usual Japanese archives). `rtl/wd1793.sv` already reads
  D88/D77 containers (from FM-7_MiSTer). Native tapes are MZT/CAS; the format is the MZ-80B/2000 one.
- MZ-2000 software (tapes and disks) runs in compatibility mode; MAME's `mz2500` also lists `mz2000_flop` as compatible.

## 4. Feasibility for this core

### Reusable

| Block | Notes |
|---|---|
| T80 (`rtl/T80`) | 6 MHz from an accumulator CE, plus the M1 and VRAM wait states. |
| i8255, i8253 (`rtl/i8255`, `rtl/i8254`) | Same chips; different wiring. |
| Z80 PIO (`rtl/z8420`) | Keyboard port. Needs IM 2 daisy chain with the new interrupt block. |
| MB8876 (`rtl/wd1793.sv`, `rtl/mz_fdc.sv`) | D88 support exists; add 80-track 2DD, 4 drive selects, the DE density latch. |
| Tape (`rtl/cmt.vhd`, `rtl/tape_image.sv`) | MZ-80B/2000 signalling and APSS already work here. |
| MZ-2000 mode logic (`rtl/mz80b/mz80b.vhd`) | Decode and display rules to copy into the MMU "mode 2/3" path and the CRTC's 2000/80B drawing. Not reusable as a block: on the 2500 those modes run through the 2500 MMU and CRTC. |
| hps_io, OSD, MGL loading, sim harness | As is. |

### New

| Block | Size / notes |
|---|---|
| MMU | Small: 8 x 6-bit page registers, mode register, IPL-reset vs. special-reset maps. |
| Interrupt controller | Small: four vectors (C6/C7), IM 2 acknowledge. |
| YM2203 | Reuse jotego's `jt03` (in the jt12 repo). It is already integrated in the local `../FM-7_MiSTer/rtl/jt12/` with an audio mixer (`AUDIOMIX.v`). Roughly 2-3k ALMs (estimate). |
| RP5C15 RTC | Small. Seed from MiSTer's `RTC` time bits in hps_io. MSX/X68000 cores have RP5C01/RP5C15-style models to borrow. |
| Video controller | The bulk of the work. Text (40/80 columns, 3 line heights, attributes, PCG combine, kanji via ROM), four graphics layouts, windows, X/Y scroll, priority, 16/256/4096 palettes, plane latches and compare reads, VRAM wait generation. The v2 VideoController doesn't cover any of this. MAME and CSP disagree on details; CSP is more complete. |
| Kanji/dictionary access | Through MMU pages 39/3A and ports B8-B9/CE/CF. The text display also reads kanji glyphs per character cell, so the kanji ROM must be readable by the raster. |
| Keyboard | New matrix (FM-7-like layout, Japanese keys: KANA, GRAPH, HENKAN, MUHENKAN). |
| Mouse | Z80 SIO channel B, X68000-style serial mouse. Could come late; few games need it. |

### Memory budget

| Item | Bits |
|---|---|
| Main RAM 256 KB (128 KB minimum) | 2.10 Mbit (1.05) |
| Graphics VRAM 128 KB (64 KB minimum) | 1.05 Mbit (0.52) |
| Text VRAM 6 KB + PCG 8 KB + CG 2 KB | 0.13 Mbit |
| IPL 32 KB | 0.26 Mbit |
| Kanji 256 KB + kanji2 128 KB | 3.15 Mbit |
| Dictionary 256 KB + phone 16 KB | 2.23 Mbit |
| Total | about 8.9 Mbit; minimum machine without dictionary about 5.2 Mbit |

The DE10-Nano has 5.66 Mbit and the current core uses 79% of it, so none of this fits beside the existing models. Plan:

- **SDRAM:** main RAM, kanji, kanji2, dictionary, phone ROM. A 6 MHz Z80 cycle (500 ns at minimum) leaves plenty of SDRAM time.
  The kanji ROM also feeds the text raster: it needs a prefetch (one glyph row per character cell; 80 cells x 2 bytes per line),
  or a small block-RAM glyph cache. FM-7_MiSTer moved its kanji ROM to SDRAM for the same reason (`../FM-7_MiSTer/TODO.md`).
- **Block RAM:** graphics VRAM (the raster reads all 4 planes, up to 8 for 256 colours, every 8 pixels), text VRAM, PCG, CG ROM,
  palette, IPL (or IPL in SDRAM too). About 1.5 Mbit, so it fits comfortably in a standalone core.
- **ALMs:** estimate 12-18k for the whole machine (T80 ~3k, jt03 ~2-3k, FDC ~2k, video 4-6k, SDRAM controller, glue, framework
  ~5k). Fine on its own; tight if added to the current 19.4k-ALM core.

### Clocks and video

The MZ-2500 runs from a 24 MHz crystal (CPU, OPN, 8253) and a 21.477 MHz (6 x NTSC subcarrier) dot clock for 400 lines, 14.32 MHz
for 200 lines. A clk_sys of 85.909 MHz (4 x 21.477) gives both dot clocks as exact enables and 6/2 MHz by accumulator, in the same
style as `rtl/clkgen.vhd`. The current 70.9376 MHz (MZ-700 based) does not suit it, another reason for a separate build.

400-line mode is 24.86 kHz: HDMI through the framework scaler is fine, but analogue output needs the scaler (`vga_scaler=1`) or a
24 kHz-capable monitor; 200-line mode is 15.98 kHz and works on a CRT. Expose the front-panel 200/400-line switch in the OSD (OPN
port B bit 6), as the software adapts to it.

## 5. Recommended plan

Build it as a **separate core** (`MZ2500_MiSTer`, or a second `.qsf`/top level in this repo sharing `rtl/T80`, `rtl/i8255`,
`rtl/i8254`, `rtl/z8420`, `rtl/wd1793.sv`, `rtl/cmt.vhd`, `rtl/tape_image.sv`). Reasons: different clocks, SDRAM needed, a
different video controller, a different keyboard and OSD, and the current core is already at 79% block RAM. MZ-2000 mode is
already covered by this core's MZ-2000 model, so the 2500's compatibility mode is low priority.

Use EmuZ-2500 (CSP) as the main behavioural reference and MAME as a second opinion; build a Verilator sim first and compare frames
against EmuZ-2500 screenshots, as the MZ-800 work did with mz800emu.

| Phase | Content | Exit test | Effort |
|---|---|---|---|
| 0 | Skeleton: new top, 85.9 MHz PLL, SDRAM controller, ROM loading (IPL, CG, kanji from SD), T80 at 6 MHz with waits, MMU, interrupt block, 8255/8253/PIO, keyboard. | IPL runs in the sim (trace matches CSP's first few thousand instructions). | 3-4 weeks |
| 1 | Text CRTC: 80/40 columns, line heights, attributes, CG ROM, 200/400 line timing. | IPL boot menu on screen, sim and hardware. | 2-3 weeks |
| 2 | Floppy: MB8876 on D8-DE, 2DD D88, 2-4 drives. | Boots BASIC-M25 / a game disk to its title (text). | 1-2 weeks |
| 3 | Graphics: plane VRAM, four modes, windows, scroll, plane latches/compare, 16/256/4096 palettes, priority. | Game title screens match EmuZ-2500 frames. | 4-6 weeks |
| 4 | Kanji and PCG on the text layer (SDRAM prefetch or cache), dictionary ROM window. | Japanese BASIC and kanji-using games display correctly. | 2-3 weeks |
| 5 | Sound: jt03 OPN (port A/B wiring), beeper, mixer. RP5C15 RTC. | Music in games; clock reads MiSTer time. | 1-2 weeks |
| 6 | Tape and APSS, MZT images (reuse `tape_image.sv`); joystick; mouse (SIO B). | Native tape titles load. | 2 weeks |
| 7 | Optional: MZ-2000/80B modes through the 2500 MMU/CRTC (mode switch in the OSD, 4 MHz), MZ-2520 IPL, SASI HDD. | MZ-2000 tapes load through the 2500 IPL. | 2-4 weeks |

Total: about 17-26 weeks of part-time effort for phases 0-6; the MAME software list is the acceptance set.

## 6. Risks

- **Video detail is under-documented.** MAME is imperfect and its comments mark several guesses; CSP is better but still a model.
  Real hardware references (Oh!MZ / Oh!X articles, service manual) would help; none are in `refs/` yet.
- **Kanji fetch from SDRAM** in the raster path; FM-7_MiSTer's experience shows it needs careful prefetching and its own test.
- **Timing-sensitive software:** EmuZ-2500's changelog is mostly wait-state and VRAM-wait fixes; games and demos (Super MZ demo,
  The Black Onyx use 8253 channel 2) depend on them.
- **Copy-protected D88 disks:** `wd1793.sv` already handles several protection cases from the MZ-80B/2000 and FM-7 work, but
  2DD protected disks are untested.
- **Little test material locally:** only two titles in `software/`, both needing debugger injection. D88 images must be collected.
- **Licensing:** EmuZ-2500 is GPLv2 and MAME is BSD-3 (this driver); use them as references, not as code to translate line by
  line, to keep the core's GPLv3 clean.
